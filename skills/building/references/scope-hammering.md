# Scope Hammering

Use this when timebox pressure or scope creep appears.

## Principle

Keep quality fixed. Reduce scope.

Do not cut the package's core desired outcome. Cut secondary states, nice-to-haves, and package outside ideas.

## Questions

- Does the package desired outcome still work without this?
- Does this appear in the first integrated slice?
- Does leaving it out block future extension structurally?
- Does adding it open a new why/what decision?
- Does adding it require more appetite?

## Handling

- If it is not needed for the desired outcome, cut it.
- If it opens a new product decision, do not build it.
- If it is a recurring or boundary-relevant future candidate, reconcile it with `shapeup/parking-lot.md`.
- Otherwise record it only in the build log.
